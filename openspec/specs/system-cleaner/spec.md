# system-cleaner 规格

## Purpose

约束 PureMac 系统工具模块：作为单一 FeatureModule 承载垃圾清理、应用卸载与残留、大文件、重复文件、菜单栏 CPU/MEM/实时网速监控、MEM 内存占用菜单与应用退出；清理遵循「先看后删、默认不选中、废纸篓优先」，权限按需申请，签名与既有 TCC 授权保持稳定。

## Requirements

### Requirement: PureMac 作为单一功能模块

PureMac SHALL 作为本项目的一个 `FeatureModule`（id `systemTool`）存在，通过一个菜单分组、一个设置页 Tab 和一个原生 SwiftUI 窗口对外提供全部子功能。

#### Scenario: 模块启用与入口

- **WHEN** 用户在设置→模块中启用 PureMac
- **THEN** 菜单栏出现「PureMac」分组，且「快捷操作」子菜单出现「打开 PureMac」
- **AND** 手机面板「快捷操作」区出现同名按钮
- **AND** 设置→按钮管理→添加内置操作中可添加 `systemTool.open`

#### Scenario: 模块禁用

- **WHEN** 用户禁用 PureMac 模块
- **THEN** 菜单栏各监控状态项（CPU / MEM / 网速）、模块菜单与内置按钮入口全部消失
- **AND** 定时器停止、未完成的按需扫描取消、结果对象释放
- **AND** 状态栏展示信息的勾选状态保留；重新启用模块后按勾选恢复显示

### Requirement: 分类扫描与先看后删

清理功能 SHALL 在删除前展示每条的具体路径、大小和类别，且任何条目默认都不选中。

#### Scenario: 扫描结果默认不删

- **WHEN** 用户执行一次垃圾/缓存或大文件扫描
- **THEN** 结果列表展示每条的路径、大小、修改时间与分类
- **AND** 所有条目默认未选中，界面没有任何"选中即删"的隐式动作
- **AND** 显示可清理总大小，该数值按当前选中项实时更新

#### Scenario: 用户确认后清理

- **WHEN** 用户勾选条目并点击清理
- **THEN** 弹出确认，列出选中条目数量、总大小和"移入废纸篓"字样
- **AND** 确认后执行；若勾选了永久删除，则再次单独确认
- **AND** 结果显示成功数、跳过数与失败数
- **AND** 凡由扫描产生并展示给用户的条目（含大文件、开发缓存、Xcode 缓存、沙盒容器缓存）均须真正移入废纸篓，不得被安全校验静默跳过

#### Scenario: 扫描范围与清理范围一致

- **WHEN** 系统校验一条待清理路径是否允许删除
- **THEN** 允许范围 SHALL 与 `ScanEngine` 实际会产出条目的扫描根共享同一份定义（`SystemToolScanRoots`），两处不得各自维护清单
- **AND** 大文件扫描根（默认下载/文稿/桌面，或用户在设置页自定义的绝对目录）纳入允许范围
- **AND** 原始路径与符号链接解析后的路径都必须落在允许范围内，防止 TOCTOU 逃逸
- **AND** 系统关键路径与家目录敏感点目录（`/System`、`/etc`、`~/.ssh`、`~/Library/Keychains` 等）由 denylist 优先拒绝，不因允许范围放宽而失效
- **AND** 符号链接、SIP/immutable 保护路径、排除路径与云同步 File Provider 状态仍按既有规则跳过

#### Scenario: 扫描可取消

- **WHEN** 用户在扫描进行中点击取消或关闭窗口
- **THEN** 扫描在当前检查点停止，不产生任何删除
- **AND** 已扫描到的部分结果被丢弃或明确标注为"未完成"

### Requirement: 应用卸载与残留分级

应用卸载 SHALL 按 bundle ID 与应用容器路径发现关联文件，并对删除风险分级展示。

#### Scenario: 卸载应用

- **WHEN** 用户选择一个已安装应用并确认卸载
- **THEN** 应用包先移入废纸篓
- **AND** 列出发现的关联文件，分为"高置信残留"与"需人工核对"两组
- **AND** 只有高置信残留可批量勾选；需人工核对的项必须逐项勾选

#### Scenario: 安全策略拦截

- **WHEN** 关联文件路径命中系统路径或符号链接保护规则
- **THEN** 该路径被跳过、不可勾选
- **AND** 结果中计入跳过数并说明原因

### Requirement: 重复文件清理

重复文件功能 SHALL 以内容哈希分组，每组保留一份，其余只有经用户确认才移入废纸篓。

#### Scenario: 扫描重复文件

- **WHEN** 用户指定扫描根目录并启动
- **THEN** 按 SHA-256 内容哈希分组，忽略符号链接、包、云占位文件与 dataless 文件
- **AND** 每组显示文件大小、文件数与可释放空间
- **AND** 每组的 `keeper` 默认不选，其余默认不选

#### Scenario: 移入废纸篓

- **WHEN** 用户勾选组内文件并确认
- **THEN** 勾选文件移入废纸篓
- **AND** 该组的 keeper 与未勾选文件不受影响

#### Scenario: 扫描上限

- **WHEN** 扫描达到上游设定的文件数或目录项上限
- **THEN** 扫描停止并显示"已达到扫描上限，结果可能不完整"
- **AND** 已找到的分组仍然可查看和操作

### Requirement: 菜单栏 CPU/MEM/网速监控与进程退出

菜单栏 SHALL 常驻显示 CPU、内存占用与实时网速，三者为独立状态项、可分别点击与单独开关；应用列表 SHALL 支持退出与强制退出，并对不可退出进程明确置灰。

#### Scenario: 菜单栏采样

- **WHEN** PureMac 模块启用
- **THEN** 菜单栏新增三个独立状态项（CPU、MEM、网速）：CPU 项上下两行显示数值与标签 `CPU`，MEM 项上下两行显示占用百分比与标签 `MEM`，网速项上下两行显示 ↑上行 / ↓下行速率（内容详见「菜单栏实时网速」要求），按固定间隔刷新
- **AND** 三个状态项按 macOS 从右往左的排列规则反序创建，使从左到右呈现 CPU → MEM → 网速；数值完整不被裁切，自绘视图跟随深浅色
- **AND** 设置→PureMac 的状态栏展示信息设置里，CPU、MEM、实时网速可分别勾选，勾掉即不创建对应状态项，改动即时生效；不另设菜单栏总开关，模块启用开关即总闸
- **AND** 不显示温度、音频设备图标
- **AND** 采样只读系统 API（网速用 `getifaddrs`），不申请 TCC 权限
- **AND** 模块禁用或 App 退出时三个状态项移除、定时器停止

#### Scenario: 独立状态项点击

- **WHEN** 用户点击 CPU 或网速状态项
- **THEN** 直接打开 PureMac 窗口
- **WHEN** 用户点击 MEM 状态项
- **THEN** 弹出内存占用下拉菜单（内容详见「MEM 状态项内存占用菜单」要求），不打开主窗口

#### Scenario: 优雅退出

- **WHEN** 用户在进程列表对普通应用点击"退出"
- **THEN** 调用 `NSRunningApplication.terminate()`
- **AND** 应用按自身流程退出（可提示保存），不被强杀

#### Scenario: 强制退出

- **WHEN** 用户对进程点击"强制退出"
- **THEN** 先弹出确认，写明未保存内容会丢失
- **AND** 确认后调用 `forceTerminate()`

#### Scenario: 不可退出进程

- **WHEN** 进程是系统进程、root 进程或受 SIP 保护
- **THEN** 退出与强制退出按钮不可用
- **AND** 该行显示"系统进程不可退出"，点击不产生任何动作

### Requirement: 菜单栏实时网速

菜单栏网速项 SHALL 用公开 API 定时差分得到上下行速率，并以定宽、统一样式显示，不随数值位数变化而抖动。

#### Scenario: 网速采样

- **WHEN** 模块启用、网速开关打开
- **THEN** 系统以 `getifaddrs()` 读取活动网络接口（en*/utun*，跳 lo0）的累计收发字节，定时差分得到上下行速率（B/s）
- **AND** 累计值回绕或接口重置时速率记 0，不出现负数
- **AND** 不申请任何 TCC 权限、不依赖第三方依赖或私有 API

#### Scenario: 网速定宽与统一样式

- **WHEN** 网速速率数值位数变化（如 `17.0` → `336.0`）
- **THEN** 网速项宽度恒定、左右边界不移动，数值小数点对齐（figure space U+2007 右对齐填充到 5 字符 + 9pt 等宽数字字体 + 固定列宽，单位固定 B/s·K/s·M/s·G/s）
- **AND** ↑上行 / ↓下行两行同字号（9pt）同颜色（跟随系统 `.labelColor`），只靠箭头方向区分，不出现双字号或双色

### Requirement: MEM 状态项内存占用菜单

点击 MEM 状态项 SHALL 弹出内存占用下拉菜单（而非打开主窗口），展示点击时即时采样的内存占用排行，并提供用户应用的一键正常退出。

#### Scenario: 点击 MEM 查看内存占用

- **WHEN** 用户点击菜单栏的 MEM 状态项
- **THEN** 弹出菜单，顶部显示内存占用百分比标题（与状态项当前显示一致），下方按常驻内存降序列出运行中应用（图标、名称、占用大小）
- **AND** 底部显示提示「关闭将直接退出程序，请先保存重要数据」
- **AND** 数据为点击时即时采样（`proc_pidinfo`，零权限），不依赖主窗口是否打开、不常驻额外后台任务

#### Scenario: 关闭一个用户应用

- **WHEN** 用户点击某个 `/Applications` 或主目录下应用行的「关闭」按钮
- **THEN** 系统通过 `NSWorkspace.terminate()` 请求该应用正常退出（非强制），安全策略与主窗口进程页共用同一份 `ProcessTerminationPolicy`
- **AND** 菜单刷新，移除该行

#### Scenario: 系统进程不可关闭

- **WHEN** 菜单项对应的进程不是用户应用（路径不在 `/Applications` 或主目录）
- **THEN** 该行的「关闭」按钮禁用，点击无效果

### Requirement: 完全磁盘访问按需申请

PureMac SHALL 在未获得完全磁盘访问时隐藏依赖该权限的内容，而不是展示不完整结果：清理、大文件、重复文件、概览四个 Tab 整块替换为占位说明，卸载页的残留区同样替换并禁用扫描，页面上不出现任何列表、合计或"可清理大小"。

#### Scenario: 未授权打开扫描类页面

- **WHEN** 用户未授予完全磁盘访问并打开概览 / 清理 / 大文件 / 重复文件
- **THEN** 只显示「需要「完全磁盘访问权限」」+ 一句原因 + 「打开系统设置授权」按钮
- **AND** 不渲染扫描按钮、条目列表与合计

#### Scenario: 未授权打开卸载页

- **WHEN** 用户未授予完全磁盘访问并打开应用卸载
- **THEN** 左侧应用列表照常显示（不需要该权限）
- **AND** 右侧残留区替换为同一占位，「扫描残留」按钮禁用

#### Scenario: 授权后恢复

- **WHEN** 用户授予完全磁盘访问并重新打开或刷新页面
- **THEN** 恢复正常的扫描界面与完整结果

### Requirement: 签名与授权稳定

PureMac SHALL 不改变本项目的签名身份、Bundle ID、runtime 标志与既有 TCC 授权。

#### Scenario: 构建与覆盖安装

- **WHEN** 按构建流程打包并覆盖 `/Applications/MacAppControlDeck.app`
- **THEN** 使用固定身份签名，designated requirement 仍为 certificate root 形式
- **AND** `verify-signing.sh` 校验通过
- **AND** 辅助功能、输入监控、屏幕录制、自动化授权不需重新授予

#### Scenario: 无特权 helper

- **WHEN** 用户使用 PureMac 的任何功能
- **THEN** 不出现管理员密码弹窗、不安装 privileged helper
- **AND** 不请求与内存释放相关的系统级权限

### Requirement: PureMac 窗口统一信息架构

PureMac 窗口 SHALL 使用一套统一信息架构：保留顶部页签导航，内容区按「入口 → 扫描 → 结果 → 确认」四层交互组织，各页共用统一组件，不得各自实现分散的标题、统计行或操作。

#### Scenario: 打开窗口

- **WHEN** 用户打开 PureMac 窗口
- **THEN** 窗口顶部显示「概览 / 垃圾清理 / 应用卸载 / 大文件 / 重复文件 / 进程」页签，当前页签有强调态
- **AND** 内容区顶部显示当前页标题、副标题与主操作，底部为统一 StatusBar
- **AND** 尚未扫描的页展示统一入口卡（图标 + 标题 + 副标题 + 单个主按钮），不叠加筛选条、统计行或脚注

#### Scenario: 页签切换

- **WHEN** 用户切换页签
- **THEN** 只有内容区替换，顶部页签与 StatusBar 结构保持不变
- **AND** 页签切换不重建已完成的扫描结果

### Requirement: 操作与状态就近呈现

扫描、取消、清理、停止等操作 SHALL 靠近其作用对象，底部状态栏只呈现全局状态，不得同时承担批量操作与全局状态两种语义。

#### Scenario: 待扫描

- **WHEN** 当前页尚无结果
- **THEN** PageHeader 主按钮显示「扫描 / 开始扫描」
- **AND** 内容区显示居中的空态，不叠加筛选条、统计行或脚注
- **AND** StatusBar 显示「就绪 · 上次扫描 …」

#### Scenario: 扫描中

- **WHEN** 扫描进行中
- **THEN** 内容区显示统一扫描态：当前路径 + 不定长进度条 + 已检查数量，不显示百分比数字
- **AND** StatusBar 同步显示当前路径，不显示百分比
- **AND** 用户点击取消后，弹出二次确认（文案含「进度丢失，下次需重新开始」），确认后扫描在当前检查点停止且不产生删除

#### Scenario: 有结果

- **WHEN** 扫描完成且存在结果
- **THEN** 表格上方显示「共 N 项 · 总大小 / 已选 M 项 · 选中大小」与「全不选 / 清理选中」
- **AND** 清理按钮只在有选中项且空闲时可用
- **AND** StatusBar 不再显示重复的清理按钮

### Requirement: 危险操作分层确认

清理、永久删除、卸载与强制退出 SHALL 在统一弹窗中展示对象、数量与大小，并按危险程度分层确认。

#### Scenario: 移入废纸篓

- **WHEN** 用户确认清理
- **THEN** 弹窗列出条目数量、总大小与「移入废纸篓」文案
- **AND** 默认不勾选永久删除

#### Scenario: 永久删除

- **WHEN** 用户在确认弹窗中开启永久删除
- **THEN** 出现单独的二次确认，明确「不进废纸篓、不可恢复」
- **AND** 未完成二次确认前不执行删除

#### Scenario: keeper 保护

- **WHEN** 重复文件组展示
- **THEN** keeper 行显示「保留」徽标且不可勾选
- **AND** 只有其余副本可被选中删除

### Requirement: 菜单栏状态项稳定显示与入口可达

菜单栏状态项 SHALL 完整显示且不依赖易被裁切的多行富文本，PureMac 的菜单入口 SHALL 在模块启用时始终可达。

#### Scenario: CPU/MEM 状态项显示

- **WHEN** 用户启用 CPU 或 MEM 状态项
- **THEN** 状态项以自定义绘制视图分两行显示数值与标签，数值行完整不被菜单栏边缘裁切
- **AND** 两行文字在状态项高度内垂直居中，跟随系统深浅色

#### Scenario: 菜单入口可见

- **WHEN** PureMac 模块启用
- **THEN** 菜单栏显示滑块样式主入口图标（非调试残留文字）
- **AND** 下拉菜单包含「PureMac」二级分组，含「打开 PureMac」与「PureMac 设置」
- **AND** 点击 CPU / 网速状态项可直接打开 PureMac 窗口；点击 MEM 状态项弹出内存占用菜单（见「MEM 状态项内存占用菜单」要求）
