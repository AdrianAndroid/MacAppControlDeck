# status-bar Specification

## Purpose

定义状态栏的公共注册层：模块只声明条目，公共层负责独立渲染（一条状态项一个条目）、固定顺序、开关持久化与模块联动。

## Requirements

### Requirement: 条目注册与独立渲染

模块 SHALL 通过 `StatusBarEntry` 注册条目；每个条目 MUST 渲染成独立的 `NSStatusItem`（一条状态项只承载一个条目），状态栏先后由 `order` 决定，不随启动顺序变化。`groupID` 仅用于设置页归类。当前条目共五条：CPU / MEM / 网速 / 日历 / 区域截图。

#### Scenario: 五条条目
- **WHEN** 全部模块启用且五个条目都可见
- **THEN** 状态栏出现五条独立状态项，彼此紧邻（每条只占内容宽度）
- **AND** 三条监控项各显示自己的数值，日历与区域截图各显示一个固定宽度的图标，都不与其他条目合并在一个胶囊里

#### Scenario: 点击各自菜单
- **WHEN** 点击任意一条状态项
- **THEN** 只触发该条目的动作，菜单弹在这条状态项正下方
- **AND** CPU 弹「占用最高的应用 + 打开 PureMac…」，MEM 弹内存排行，网速弹 ↑/↓ 速率菜单，日历弹月历浮层，区域截图直接进入框选

#### Scenario: 全部关闭
- **WHEN** CPU / MEM / 网速三个条目全部关闭或 PureMac 模块被禁用
- **THEN** 三条监控状态项全部消失，不残留空壳
- **AND** 日历项由万年历模块独立控制，不受三条监控项开关影响

#### Scenario: 位置持久化
- **WHEN** 用户 ⌘-拖动调整其中一条状态项的位置
- **THEN** 重启后五条的相对顺序保持（每条状态项独立 `autosaveName`）

### Requirement: 状态项不复用分段命中

一条状态项只承载一个条目时，MUST 由 `NSStatusBarButton` 的 action 直接转发给该条目，不得再按坐标做分段命中。

#### Scenario: 按钮转发
- **WHEN** 用户在状态项上按下并抬起左键
- **THEN** 直接调用该条目的 `activate(from:)`，命中判断只可能是这一个条目

### Requirement: 开关与模块联动

条目的可见性 SHALL 由「模块启用」与「用户勾选」共同决定；模块关闭时设置页开关置灰、勾选保留、状态栏移除，重新启用后按勾选恢复。

#### Scenario: 模块关闭
- **WHEN** 用户在 设置 → 模块 关闭 PureMac
- **THEN** 状态栏三条监控项立即消失
- **AND** 设置 → 状态栏 中三条监控项变灰不可点，勾选状态保留
- **AND** 日历项由万年历模块单独联动，关闭万年历模块时立即消失并关闭已弹出的面板

#### Scenario: 旧偏好迁移
- **WHEN** 从旧版本升级
- **THEN** `systemTool.menubar.showCPU/showMEM/showNetSpeed` 自动迁移到 `statusbar.systemTool.*`，首次渲染与升级前一致

### Requirement: 主图标不受影响

应用控制台主菜单图标 SHALL 保持独立状态项，不参与分组，也不受条目开关影响。

### Requirement: 日历图标状态项与月历下拉

万年历模块启用时 SHALL 注册 `calendar.panel` 条目：状态栏只显示日历图标，点击弹出**自绘无边框浮层**的双月面板而不是 `NSMenu` 或独立窗口；浮层不得显示系统箭头。

#### Scenario: 双月页面
- **WHEN** 面板打开
- **THEN** 一次显示当月 + 下月两页月历，标题为「yyyy年M月 – M月」（跨年显示两个年份）
- **AND** 每页只构建 5–6 行日期格，不预加载前后一年

#### Scenario: 整页翻动
- **WHEN** 点击 `‹` / `›` 或在面板上滚动鼠标滚轮
- **THEN** 整个面板按整月切到上一页/下一页，不滚动内容
- **AND** 触控板一次手势及惯性阶段只翻一页

#### Scenario: 回到今天
- **WHEN** 面板标题右侧显示 `‹ / 今天 / ›`
- **THEN** 「今天」是带文字的胶囊按钮，不是无标签圆圈
- **AND** 点击后选中今天并把页码切回当月

#### Scenario: 节日显示模式
- **WHEN** 设置 → 万年历选择「日期下方小字」
- **THEN** 支持「关 / 精简 / 全显示」，默认精简
- **AND** 关：不显示农历/节气/节日；精简：只显示节气与传统节日；全显示：显示全部农历/节气/节日
- **AND** 切换模式不改变网格高度；底部只有一组分段开关，不再有 `⋯` 菜单

#### Scenario: 小字可读性
- **WHEN** 面板渲染节气、节日或其他节日性小字
- **THEN** 使用对应颜色的胶囊底 + 高亮文字，而不是直接压在玻璃背景上的半透明小字
- **AND** 普通农历日仍为低对比纯文字，字号不小于 9.5pt

#### Scenario: 农历标记而非日程
- **WHEN** 面板渲染任意日期格
- **THEN** 显示公历数字、按模式过滤后的小字、今日蓝色描边与休/班书签
- **AND** 书签贴在数字右上角，今日描边不会遮住书签
- **AND** 不读取 EventKit 日程、不申请日历权限

#### Scenario: 打开完整万年历与设置
- **WHEN** 用户点击面板底部的「完整万年历」或「设置」
- **THEN** 关闭面板并打开现有 `CalendarWindowView` 独立窗口，或定位到设置 → 万年历

#### Scenario: 关闭与联动
- **WHEN** 用户再次点击日历图标、点击面板外部、按 Esc、或关闭万年历模块
- **THEN** 面板在**第一次**点击外部时就关闭，不需要再点第二次
- **AND** 点击状态栏其他位置也会关闭；模块关闭时状态项与面板立即消失

#### Scenario: 外观一致
- **WHEN** 面板显示
- **THEN** 圆角、1px 描边与深色玻璃背景自绘，颜色一致
- **AND** 不出现系统 popover 的三角箭头或与背景不一致的边缘

### Requirement: 日历浮层的位置与外观

日历浮层 SHALL 以状态栏日历图标为锚点显示在图标下方，并水平限制在当前屏幕可见区域内。

#### Scenario: 靠近屏幕边缘
- **WHEN** 日历图标贴近屏幕左/右边缘
- **THEN** 浮层被水平夹紧在可见区域内，不会被裁掉

### Requirement: 区域截图状态项

截图与录屏模块启用时 SHALL 注册 `capture.region` 条目：状态栏显示 `rectangle.dashed` 图标，点击一次直接进入区域截图，不弹菜单、不打开独立窗口。

#### Scenario: 点击截图
- **WHEN** 用户点击状态栏的截图图标
- **THEN** 立即调用区域截图流程，出现选区覆盖层
- **AND** 不需要先展开「截图与录屏」菜单

#### Scenario: 开关与联动
- **WHEN** 在 设置 → 状态栏 关闭该条目，或关闭「截图与录屏」模块
- **THEN** 图标立即从状态栏移除；模块重新启用后按原勾选恢复
- **AND** 关闭该图标不影响菜单栏「截图与录屏」里的区域截图入口与 `F1` 快捷键

### Requirement: 状态项单击只触发一次

每个状态栏条目 SHALL 对一次鼠标点击只调用一次 `activate`，不得同时由子视图 `mouseDown` 和按钮 action 各触发一次。

#### Scenario: 日历首次点击
- **WHEN** App 不在前台，用户第一次点击状态栏日历图标
- **THEN** 月历 popover 立即显示并保持打开
- **AND** 不会先打开再立即关闭

#### Scenario: 再次点击
- **WHEN** 日历 popover 已打开，用户再次点击日历图标
- **THEN** popover 关闭，行为与其他菜单栏 popover 一致

#### Scenario: 不抢设置窗口
- **WHEN** 设置窗口处于打开或后台状态，用户点击状态栏日历图标
- **THEN** 只显示日历 popover
- **AND** 设置窗口不会被激活带到最前

#### Scenario: 菜单类条目不受影响
- **WHEN** 用户点击 CPU / MEM / 网速条目
- **THEN** 对应菜单仍只打开一次，点击外部关闭
