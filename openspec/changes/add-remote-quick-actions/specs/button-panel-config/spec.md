# button-panel-config 规格增量（delta）

## MODIFIED Requirements

### Requirement: 按钮的创建与绑定应用

用户 SHALL 能在 Mac 端新增按钮，按钮分为**应用按钮**（绑定一个目标应用）与**快捷操作按钮**（绑定一个按键组合）；两者创建后共用同一份配置与排序。

#### Scenario: 新增按钮并选择应用

- **WHEN** 用户在 Mac 端点击"添加应用按钮"并从应用列表（按 Bundle ID 枚举本机已安装应用）选择一个应用
- **THEN** 创建一条类型为"应用"的按钮配置：id（UUID）、类型、显示名、Bundle ID、应用路径缓存、排序号
- **AND** 按钮显示名默认取应用显示名，可随后修改

#### Scenario: 新增快捷操作按钮

- **WHEN** 用户点击"添加快捷操作"并选择预设或自定义组合
- **THEN** 创建一条类型为"快捷操作"的按钮配置：id（UUID）、类型、显示名（默认取组合符号，如 ⌘C）、组合定义（修饰键集合 + 主键）、排序号
- **AND** 创建后出现在「快捷操作」分组，不影响应用按钮的排序

### Requirement: 按钮排序

用户 SHALL 能调整按钮在面板中的显示顺序；同一分组内独立排序。

#### Scenario: 上移或下移

- **WHEN** 用户在 Mac 端对某按钮执行上移/下移（或拖拽排序）
- **THEN** 同一分组内按钮的排序号更新并写回持久化文件，手机端刷新后按新顺序展示
- **AND** 不同分组之间的排序互不影响

## ADDED Requirements

### Requirement: 快捷操作按钮的编辑

用户 SHALL 能重命名、编辑组合、删除快捷操作按钮；删除前必须确认。

#### Scenario: 编辑组合

- **WHEN** 用户对快捷操作按钮选择"编辑组合…"
- **THEN** 以录制或拼凑方式修改组合并保存
- **AND** 按钮显示名可在编辑界面一并修改

#### Scenario: 删除快捷操作

- **WHEN** 用户删除某个快捷操作按钮
- **THEN** 弹出确认对话框并显示按钮名称与组合符号
- **AND** 只有确认后才删除

### Requirement: 旧配置兼容迁移

系统 SHALL 在读取旧版 `buttons.json`（无类型字段）时将其视为应用按钮，并在下次写入时补齐字段，不丢失任何既有配置。

#### Scenario: 升级后读取旧配置

- **WHEN** 已存在的配置文件缺少类型与组合字段
- **THEN** 读取结果中这些按钮全部按"应用按钮"处理，面板与 Mac 端显示不变
- **AND** 后续任何写入操作使用新结构持久化，旧字段兼容保留

#### Scenario: 配置文件不被破坏

- **WHEN** 旧配置文件中存在未知字段
- **THEN** 读取与写回过程不删除未知字段（宽容解析）
- **AND** 文件损坏时仍按既有降级策略处理，不阻塞程序启动
