# remote-web-panel 规格增量（delta）

## MODIFIED Requirements

### Requirement: 按钮面板主界面

手机端 SHALL 采用「上下双区」布局：顶部为应用按钮区（占剩余高度，**上下滑动**），底部为快捷操作区（最多 2 行，横向滑动，高度约为屏幕 1/3；动作 ≤3 个时收缩为 1 行）；每个按钮清晰显示图标/组合符号与名称，适合手指点击。

#### Scenario: 正常展示按钮

- **WHEN** 已配对设备加载面板并成功获取按钮列表
- **THEN** 顶部区域按网格显示应用按钮（图标 + 名称），底部固定区域按 1–2 行网格显示快捷操作按钮（组合符号 + 名称）
- **AND** 按钮足够大（点击区域建议 ≥ 72pt），两区各自按分组内排序展示

#### Scenario: 应用按钮超出屏幕

- **WHEN** 应用按钮数量超过顶部区域可容纳的行数
- **THEN** 顶部区域内部可上下滑动，底部快捷操作区保持固定可见，不随应用区滚动移出屏幕
- **AND** 滚动过程中连接状态条与底部区不抖动、不遮挡

#### Scenario: 快捷操作超出底部区域

- **WHEN** 快捷操作按钮数量超过底部区域一屏可容纳的数量
- **THEN** 底部区域内部可左右滑动（横向滚动）；≤3 个动作时只显示 1 行，≥4 个时固定 2 行
- **AND** 不挤压顶部应用区的可用高度，不换行也不纵向滚动

#### Scenario: 仅有一组按钮

- **WHEN** 用户尚未配置任何快捷操作按钮（或只配置了快捷操作）
- **THEN** 空分组不显示对应区域，剩余区域占满可用空间
- **AND** 页面仍保持简洁，不出现复杂管理入口

#### Scenario: 竖屏与横屏自适应

- **WHEN** 用户在 iPhone 竖屏或横屏使用面板
- **THEN** 应用区竖屏 2 列、横屏 3–4 列（纵向滚动）；快捷操作区最多 2 行横向滚动，按钮列宽随屏幕方向调整
- **AND** 内容不受刘海/安全区遮挡（含底部 Home Indicator 安全区），同一页面在 iPad 与常见 Android 浏览器可用
### Requirement: 点击按钮的操作反馈

面板 SHALL 对每次点击给出明确反馈，并按按钮类型区分"请求已发送"与"已确认结果"两级语义。

#### Scenario: 请求已发送

- **WHEN** 用户点击某按钮且请求已发出
- **THEN** 该按钮立即显示进行中状态（应用按钮为"正在打开…"，快捷操作为"正在发送…"）

#### Scenario: 请求已确认

- **WHEN** 服务端返回成功且状态为 `launched`、`activated`
- **THEN** 反馈"已启动"或"已切换"，随后按钮状态恢复空闲

#### Scenario: 快捷操作已发送

- **WHEN** 快捷操作按钮返回 `sent`
- **THEN** 反馈"已发送快捷键"，随后按钮状态恢复空闲
- **AND** 不显示"应用已响应"之类无法确认的措辞

#### Scenario: 服务端无法确认

- **WHEN** 服务端返回 `unconfirmed`（如已激活但无法确认窗口状态）
- **THEN** 反馈"已发送激活请求，但未能确认窗口状态"，不显示虚假的"已切换"

#### Scenario: 失败反馈

- **WHEN** 服务端返回 `app-not-found`、`activation-failed`、`accessibility-required`、`secure-input` 或网络失败
- **THEN** 显示对应中文错误说明（如"应用未找到（可能已卸载）""需要辅助功能权限"），不重试到无限循环

#### Scenario: 请求期间的交互保护

- **WHEN** 某按钮的触发请求尚未返回
- **THEN** 该按钮禁用并显示状态，防止重复触发
- **AND** 其他按钮仍可操作

## ADDED Requirements

### Requirement: 快捷操作按钮的呈现

快捷操作按钮 SHALL 以按键组合符号为主信息展示，并与应用按钮在视觉上可区分。

#### Scenario: 组合符号展示

- **WHEN** 面板渲染快捷操作按钮
- **THEN** 主标签显示组合符号（使用 ⌘ ⌃ ⌥ ⇧ 与键名，如 ⌘C、⌃→、F5）
- **AND** 下方显示用户可编辑的名称

#### Scenario: 桌面切换按钮

- **WHEN** 面板渲染"桌面左/桌面右"按钮
- **THEN** 显示方向符号（← / →）与"桌面"文案
- **AND** 与普通组合按钮使用一致的状态反馈机制
