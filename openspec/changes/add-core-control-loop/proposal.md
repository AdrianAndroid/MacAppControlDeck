# 变更提案：add-core-control-loop

## 修改目的

把一台闲置 iPhone 变成 Mac 应用快捷控制台：在局域网内，手机打开网页面板，点击应用按钮即可在 Mac 上启动或激活对应应用，并尽可能切换到该应用所在的桌面空间。

本变更交付**第一阶段（最小可行版本）的完整闭环**，同时把第二阶段的体验项纳入能力规格与任务清单，便于后续按序归档。

## 修改内容

新增 6 个能力（均为全新增）：

| 能力 | 职责 |
| --- | --- |
| `app-control` | 按 Bundle ID 启动/激活/恢复 Mac 应用，处理隐藏、最小化、空间切换等边界行为，并如实反馈结果 |
| `button-panel-config` | 按钮的增删改、排序、图标自动填充、本地 JSON 持久化 |
| `pairing-auth` | 一次性配对码、设备凭证签发与校验、撤销配对、防跨站与 DNS 重绑定 |
| `lan-api` | 局域网 HTTP 服务：白名单端点（配对、按钮列表、激活命令、健康检查）+ 静态面板托管 |
| `remote-web-panel` | 手机端自适应网页：大按钮网格、连接状态、操作反馈、iOS 主屏幕支持 |
| `host-app-shell` | Mac 端宿主程序：菜单栏常驻、状态/地址/二维码展示、按钮与设备管理界面 |

第一阶段的验收闭环：Mac 端显示局域网地址 → iPhone Safari 打开面板 → 完成配对 → Mac 端添加一个应用按钮 → 手机点击 → Mac 启动或激活该应用 → 手机看到明确反馈 → Mac 程序重启后配置仍在。

第二阶段（同规格、分批实现）：图标与增删改排序的完整体验、隐藏/最小化窗口的合理处理、断线重连、配对设备管理界面、二维码、添加到主屏幕体验、使用说明与故障排查。

## 明确不做的（Non-goals）

- **禁止**把 Mac 端做成执行任意 shell 命令的网关；手机只能调用白名单动作。
- 不做窗口**永久置顶**（floating above all apps）——macOS 对第三方应用没有可靠的通用方案，本项目的"置顶"专指**切换到前台**。
- 不承诺 Mac 休眠/锁屏/退出后仍可控制；手机端应能感知不可用。
- 不做 Mac 开机自启的默认开启、不修改系统设置、不开启远程登录。
- 第一版不做手机端按钮管理（Mac 端管理，手机端只读）；后续如做，须在已配对状态下进行。
- 不做多用户/账号体系；单用户局域网场景。

## 影响

- 全新项目，无既有代码受影响。
- 需要的 macOS 权限：默认为零（启动/激活走 NSWorkspace/NSRunningApplication）；仅在 AppleScript 后备激活路径启用时触发"自动化"权限弹窗，届时须说明原因。
- 手机端不请求任何 iOS 特殊权限（网页无后台能力，按其实际限制设计）。
