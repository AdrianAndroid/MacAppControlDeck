# Change: 修正副屏天气首次加载的误导文案

## Why

副屏页面在首次请求 `/api/weather` 返回前，HTML 初始状态直接写着「天气暂不可用」。用户刚打开页面（或网络慢、断网恢复瞬间）看到的是这句**失败文案**，误以为天气功能坏了；实际接口正常，只是请求尚未完成。用户后续确认根因是当时断网。

## What Changes

1. 页面初始状态改为「天气加载中…」，不再假装已失败。
2. 请求失败且无明确上游原因时，显示「天气加载失败，正在重试…」；有明确原因（如未配置凭据、Host 错误、网络不可达）时照实显示。
3. 失败后 8 秒自动重试一次；成功后清除重试定时器。重试时状态回到「天气加载中…」。
4. `ScreenHTML.version` 升到 `2026-11-25.2`，确保浏览器拿到新页面。
5. 同步 `remote-web-panel` 主规格中天气失败场景的文案与重试要求。

## Capabilities

- `remote-web-panel`（修改）：天气栏首次加载与失败态的文案、重试行为。

## Impact

- `Sources/MacAppControlDeck/Panel/ScreenHTML.swift`（页面 HTML/JS、版本号）。
- `openspec/specs/remote-web-panel/spec.md`（天气失败场景）。
- 用户可见：打开副屏先看到「天气加载中…」，成功即显示真实天气；断网时明确报错并自动重试。

## Non-goals

- 不改天气数据链路、凭据存储与配置 UI。
- 不做离线天气缓存（现有服务端缓存与「已过期」标记保持不变）。
