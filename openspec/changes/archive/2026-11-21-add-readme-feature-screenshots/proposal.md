# 提案：README 功能截图与使用路径

## Why

README 是项目对外的主要入口，但此前几乎全是文字。菜单栏、设置页、截图/录屏、UI 草图与手机面板的真实界面都需要读者从大段文字里自行想象，新用户很难快速判断：

- 菜单栏到底长什么样、入口在哪；
- 设置页有哪些模块、权限状态如何显示；
- 截图/录屏有哪些能力、选区是什么交互；
- UI 草图与内置素材库的实际形态；
- 手机端如何配对、配对后按钮如何排列。

用户明确要求：把“所有功能截图、使用方式截图”放进 README，并推送到 GitHub。这里的“功能截图”指真实运行界面，不是示意图或设计稿。

## What Changes

- 新增 `Docs/images/readme/`，保存 14 张实机/真实数据截图，合计约 1.4 MB。
- README 顶部增加「菜单栏 + 手机面板」总览；按使用路径在对应章节插入截图，而不是全部堆在文末。
- 新增三个图文使用章节：
  - 「截图、录屏与视频剪辑」：子菜单、设置页、区域截图选区、5 步使用路径；
  - 「UI 草图」：画板、精选素材库、5 步使用路径；
  - 「设置界面」：通用、菜单、模块、UI 草图、设备页。
- 手机端章节增加首次配对页与已配对面板。
- 修正 README 测试数量：40 项 → 51 项（与最近一次测试结果一致）。
- 在 `Docs/archive/` 与 `openspec/changes/archive/` 各归档一份需求记录；README 的「归档」索引加入链接。

**非目标**：

- 不新增或修改任何功能代码；
- 不重拍标注编辑器、录制 HUD、视频剪辑等运行态临时界面（本次以选区截图 + 设置页 + 步骤说明表达）；
- 不发布新版本、不改 Release 资产；
- 不把截图做成营销视觉稿；截图以“可核对真实界面”为准。

## Capabilities

### New Capabilities

- `project-documentation`：README 作为主要入口的截图与使用路径要求，包括截图真实性、目录与链接、隐私与体积约束、界面变化后的维护义务。

### Modified Capabilities

- 无。本次是文档与截图资产，不改变 `remote` / `capture` / `sketch` 的运行时行为。

## Impact

- 文档：`README.md`、`Docs/images/readme/`（14 张 PNG）、`Docs/archive/2026-11-21-readme-screenshots/SUMMARY.md`。
- OpenSpec：本变更归档目录与 `openspec/specs/project-documentation/spec.md`。
- 代码/权限/API/数据：无变化。
- 用户可见入口：无。本次不新增功能，因此不触发内置快捷打开按钮规则。
