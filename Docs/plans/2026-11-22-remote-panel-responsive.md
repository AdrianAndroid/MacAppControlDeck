# 电脑控制 · 手机浏览器面板横竖屏适配

- 状态：已实现并覆盖安装，生产版本 `2026-11-22.2`；多尺寸验证与签名校验通过，待真实 iPhone Safari 手测。
- 范围：`Sources/MacAppControlDeck/Panel/PanelHTML.swift` 提供的手机面板。
- 非目标：不拆成两个包；不改按钮数据模型；不改 `/api/buttons`、`/api/activate` 协议；不做按钮拖拽排序。

## 1. 现状与问题

改造前版本 `2026-11-20.5`，结构是「标题栏 + 应用区 + 底部快捷操作区」，两个区都支持横向整页滑动和页点。

现状布局参数：

- 竖屏：应用区 2 列；快捷操作 4 列 × **固定 3 行**，每页 12 个。
- 横屏：应用区 4 列；快捷操作 6 列 × **固定 3 行**，仍然贴底，每页 18 个。
- 快捷区高度写死为 `scRows * 72 + (scRows - 1) * 10 + 2`，即约 236px。
- 应用区行数按实测高度计算，横屏 fallback 3 行、竖屏 fallback 4 行。
- `@media (orientation: landscape)` 只改了左右 padding 和按钮最小高度，没有真正的横屏布局。

由此产生的问题：

1. 横屏时底部快捷区仍占约 236px，应用区被压扁，出现「横屏反而看不全」。
2. 快捷区固定 3 行，竖屏无法收敛成 2 行。
3. 横屏没有「左侧应用 + 右侧快捷」的分栏，窗口宽度没有被利用。
4. 页面仍可能产生纵向滚动/回弹，交互不像原生 App。
5. 尺寸写死，窗口高度变化时最后一行容易被截断。

## 2. 需求口径

按当前描述，需求收敛为 6 条：

1. **横竖屏两套布局**：竖屏上下双区，横屏左右双栏；不是简单换列数。
2. **沿用原有格式**：保留标题栏、状态胶囊、应用区、快捷操作区、配对页、toast、页点、按钮状态。
3. **像原生 App，不能随意拖动**：禁止整页纵向滚动/回弹/下拉刷新，禁止按钮拖拽排序，禁止长按菜单、文本选择、双击缩放；**保留横向翻页和页点**。
4. **竖屏快捷操作 2 行**：底部快捷操作从 4×3 改为 4×2，不再出现第 3 行。
5. **横屏右侧 2 列 × 4 行方形按钮**：快捷操作移到右侧独立栏，固定 2 列 × 4 行，靠上排；应用区在左侧。
6. **按窗口平均分配**：用 flex/grid 的 `minmax(0, 1fr)` 分配可用宽高，不写死快捷区高度；横屏、竖屏、窗口缩放都不能裁切内容。

> 术语确认：下面把「跨界操作」按**底部“快捷操作”区**理解。如果实际指的是“跨桌面/跨空间切换”那一组按钮，需要把第 4 条改成只约束那一组。

## 3. 推荐布局

### 3.1 竖屏

```text
┌──────────────────────────────┐
│ 标题栏                 状态胶囊 │
├──────────────────────────────┤
│ 应用                          │
│  ┌─────┐ ┌─────┐              │
│  │ App │ │ App │   2 列 × N 行 │
│  └─────┘ └─────┘              │
│  ● ● ●                        │
├──────────────────────────────┤
│ 快捷操作                      │
│  ┌──┐ ┌──┐ ┌──┐ ┌──┐          │
│  │  │ │  │ │  │ │  │  4 列 × 2 行│
│  └──┘ └──┘ └──┘ └──┘          │
│  ● ●                          │
└──────────────────────────────┘
```

- 应用区：2 列，行数按可用高度计算，建议 3–6 行。
- 快捷操作：4 列 × 2 行，每页 8 个；超过 8 个横向翻页。
- 快捷区不再固定 236px，改为 2 行实际高度（约 150–170px，含页点）。
- 应用区吃掉剩余高度，保证不出现整页纵向滚动。

### 3.2 横屏

```text
┌──────────────────────────────────────────────┐
│ 标题栏                              状态胶囊 │
├──────────────────────────────────┬───────────┤
│ 应用 约 82%                      │ 快捷 18%  │
│ ┌────┐┌────┐┌────┐┌────┐        │ ┌──┐ ┌──┐ │
│ │App1││App2││App3││App4│        │ │快1│ │快2│ │
│ └────┘└────┘└────┘└────┘        │ └──┘ └──┘ │
│ ┌────┐┌────┐┌────┐┌────┐        │ ┌──┐ ┌──┐ │
│ │App5││App6││App7││App8│        │ │快3│ │快4│ │
│ └────┘└────┘└────┘└────┘        │ └──┘ └──┘ │
│ ┌────┐┌────┐┌────┐┌────┐        │ ┌──┐ ┌──┐ │
│ │App9││AppA││AppB││AppC│        │ │快5│ │快6│ │
│ └────┘└────┘└────┘└────┘        │ └──┘ └──┘ │
│          ● ●                    │ ┌──┐ ┌──┐ │
│                                 │ │快7│ │快8│ │
│                                 │ └──┘ └──┘ │
│                                 │     ● ●   │
└──────────────────────────────────┴───────────┘
```

- 主区改为左右双栏：右栏宽度由「4 行方形按钮」反推，约占 16–18%；左侧应用占剩余宽度。
- 左应用：4 列，行数按高度计算，建议 2–4 行。
- 右快捷：**2 列 × 4 行**，按钮为正方形，每页 8 个；超过 8 个在右栏内横向翻页。
- 右栏不再贴底，不再占用整页底部高度；应用区不再被压扁。
- 右侧 4 行**靠上排布**，不足 8 个时下方留白，不把卡片拉成长方形。

### 3.3 宽屏浏览器窗口

- 宽度 ≥ 900px 时沿用横屏左右双栏，但限制内容最大宽度（建议 1200–1280px）并居中，避免卡片被拉得过大。
- 窗口从窄变宽、从宽变窄时按同一套列数/行数算法重算，不依赖一次性 `orientationchange`。

## 4. 原生 App 交互规则

### 4.1 禁止的操作

- 整页纵向滚动、橡皮筋回弹、下拉刷新。
- 按钮拖拽、长按拖动排序、卡片拖动。
- 长按弹出菜单、文本选择、双击缩放。
- 浏览器默认的图片拖拽、链接拖拽。

### 4.2 保留的操作

- 应用区和快捷区各自横向整页滑动。
- 页点显示当前页，点击页点可跳页。
- 按钮点击态、发送中/已发送/失败状态、排队计数。
- 配对页、状态胶囊、toast。

### 4.3 实现口径（仅约束，不写代码）

- 根容器固定为视口大小：`position: fixed; inset: 0; overflow: hidden; overscroll-behavior: none`。
- 页面容器只允许横向手势：`touch-action: pan-x`；纵向手势不产生滚动。
- 分页继续用 `scroll-snap-type: x mandatory`，不引入自由拖拽。
- 保留现有 `dblclick`、`gesturestart`、二次 `touchend` 拦截；补上 `dragstart`、`contextmenu`、`selectstart` 的拦截。
- 安全区继续使用 `env(safe-area-inset-*)` 和 `100dvh`。

## 5. 尺寸与分页规则

### 5.1 列数

| 区域 | 竖屏 | 横屏 |
|---|---|---|
| 应用 | 2 列 | 4 列 |
| 快捷操作 | 4 列 | 2 列 |

### 5.2 行数与高度

- 快捷操作：竖屏 4 列 × 2 行、横屏 2 列 × 4 行；固定行数/列数，不固定像素高度。
- 应用区：按可用高度计算 `rows = floor((availableH + gap) / (minRow + gap))`，建议夹在 2–6 行。
- 卡片最小高度建议 64px，图标 40–44px，标签 12px；触控目标不小于 44×44。
- 分页容器使用 `grid-template-columns: repeat(cols, minmax(0, 1fr))`、`grid-auto-rows: minmax(0, 1fr)`，页面高度 100%，不写死 `height`。
- 不足一页时用透明占位补齐当前行列，保持网格稳定；不再按 3 行补位。

### 5.3 分页

- 竖屏快捷：4×2 = 8 个/页；12 个快捷操作 → 2 页。
- 横屏快捷：2×4 = 8 个/页；12 个快捷操作 → 2 页。
- 应用区按列数 × 动态行数分页。
- 旋转/缩放后重新计算每页容量；默认**保持当前页索引**，页数不够时夹到最后一页。
- 数据轮询刷新不改变当前页，除非按钮数量变化导致页数不足。

### 5.4 视口缩放策略

结论：**不做 `transform: scale()` 的整体等比缩放**，而是做「流式等比分配 + 尺寸夹取」。

原因：整体缩放会把小屏字号和触控目标一起缩小，把大屏卡片无限放大；且不同手机的刘海、安全区、浏览器工具栏高度不同，固定画布缩放会出现留白或裁切。

具体口径：

- 设计基准：竖屏 390×844、横屏 844×390；只作参考，不作固定画布。
- 根容器始终填满 `100dvw × 100dvh`，再扣除 `env(safe-area-inset-*)`。
- 比例关系：竖屏快捷区固定 2 行，应用区吃掉剩余高度；横屏右栏宽度由 4 行方形快捷按钮反推，左侧应用占剩余宽度。
- 基准单位建议 `--u: clamp(3.2px, 1vmin, 4.8px)`；间距、圆角、内边距按 `--u` 缩放。
- 卡片高度、图标、字号用 `clamp(min, vmin, max)`：小屏不低于触控下限，大屏不无限放大。
- 列数固定，行数动态；不同尺寸主要靠「行数变化 + 卡片夹取」适配，不是整体缩小。
- 极矮横屏（可用高度 < 340px）进入紧凑档：卡片 52–56px、间距 4–6px、字号 11px，保证右侧 4 行不裁切。
- 大屏/桌面：内容最大宽度 1280px 居中，卡片最大高度和最大宽度封顶。

典型尺寸预期：

| 屏幕 | 模式 | 应用区 | 快捷区 |
|---|---|---|---|
| 375×667 | 竖屏 | 2 列，约 4–5 行 | 4×2，8 个/页 |
| 390×844 | 竖屏 | 2 列，约 5–6 行 | 4×2，8 个/页 |
| 430×932 | 竖屏 | 2 列，约 6 行，卡片封顶 | 4×2，8 个/页 |
| 667×375 | 横屏 | 4 列，约 3 行 | 2×4 方形，8 个/页，紧凑档 |
| 844×390 | 横屏 | 4 列，约 3 行 | 2×4 方形，8 个/页 |
| 932×430 | 横屏 | 4 列，约 3 行 | 2×4 方形，8 个/页 |
| 1440×900 | 宽屏 | 4 列，最大宽度封顶 | 2×4 方形，8 个/页 |

## 7. 已确认口径

1. 「跨界操作」指底部“快捷操作”区。
2. 横屏右侧为 **2 列 × 4 行方形按钮**，靠上排布；右栏宽度按 4 行方形按钮反推，左侧应用占剩余宽度并使用 4 列。
3. 竖屏底部为 **4 列 × 2 行**。
4. 旋转后保持当前页；页数不够时夹到最后一页。
5. 横屏右侧 4 行靠上排，不足 8 个时下方留白，不撑满右栏高度。
