# 副屏桌宠「状态化」设计（2026-11-26）

> 不做任何互动（点击、拖拽、语音都不做）。副屏保持只读。
> 目标：让现有 cat / dog / robot 三只因为**真实数据**而活起来，而不是加随机动画。

## 1. 状态机

数据来源与刷新频率（都已在页面上跑）：

| 数据 | 来源 | 刷新 |
| --- | --- | --- |
| Mac 墙钟 | `/api/time` | 60s + 本地插值 |
| 天气 | `/api/weather` | 5 分钟 |
| 下班倒计时 | `/api/screen/countdown` | 1s |
| 节假休班 | `/api/screen/calendar` | 页面加载 / 换月 |

状态按下面的**优先级**依次判定，命中即停：

```
优先级  状态       条件                                   动作
 1     celebrate   工作日 且 倒计时 phase = off / 已过点      原地跳 + 星星闪过
 2     packup      工作日 且 剩余 ≤ 30 分钟                抬眼看表 + 表针摆
 3     sleep       00:00–06:00，或 周末/休日 22:00 之后     压扁不动 + Zzz 上浮
 4     rain        今天降水概率 ≥ 60%                      撑伞 + 雨滴
 5     cold        当前温度 ≤ 5°                          围巾 + 轻微发抖
 6     hot         当前温度 ≥ 30°                          汗滴
 7     idle        其余                                  走 + 呼吸
```

- 天气不可用 / 倒计时未配置时，对应条件直接跳过（回退到 idle），不弹错误
- 「休息日」判定：周末 + 月历里带 `休` 的法定假日；`班`（调休上班）按工作日处理

## 2. 视觉：道具而不是重画

四只宠物不各画一套状态，而是**共用一套道具**（都画在同一个 `viewBox 0 0 64 48` 里，随卡片高度自动缩放）：

```
 idle            sleep          rain            cold           packup        celebrate
 ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐
 │  ▄▄▄    │   │   z Z   │   │  ☂      │   │  ~~~~   │   │  ⌚     │   │  ✦ ✦   │
 │ (•ᴗ•)   │   │  ( ─ )  │   │ (•ᴗ•)▽▽ │   │ (•ᴗ•)   │   │ (•ᴗ•)→  │   │ \(•ᴗ•)/ │
 │  ╵ ╵    │   │  ▬▬▬▬   │   │  ╵ ╵    │   │  ╵ ╵    │   │  ╵ ╵    │   │  ╵   ╵  │
 └─────────┘   └─────────┘   └─────────┘   └─────────┘   └─────────┘   └─────────┘
  走 + 呼吸      压扁 + Zzz    伞 + 雨滴      围巾 + 抖     表 + 抬眼     弹跳 + 星
```

| 道具 | 几何（viewBox 单位） | 动画 |
| --- | --- | --- |
| Zzz | 3 个 `Z` 文本，自宠物头顶右侧阶梯上浮 | 每个字 2.4s 循环：位移 −8、透明度 0.2→0.9→0 |
| ☂ 伞 | 伞面半圆（r=14）+ 伞杆 1.5×18 | 轻微倾角 ±3° 呼吸 |
| 雨滴 | 4 条 1.5×5 圆角线 | 依次 0.9s 下落 + 淡出 |
| 围巾 | 2 条圆角矩形绕颈（同宠物主色系） | 无（配合身体发抖） |
| 发抖 | `transform: translateX(±0.6)` | 0.18s 交替 |
| ⌚/时钟 | 圆环 r=6 + 两根指针 | 分针 6s 转一圈（示意时间流逝） |
| 星星 | 4 个四角星 `✦` | 1.2s 循环放大淡出 |
| 汗滴 | 水滴路径 + 下滑 | 2s 循环 |

- 每只宠物只需提供 3 个锚点：`头顶`（Zzz/星星）、`身侧`（伞/雨滴）、`颈部`（围巾）
- 不新增外部素材，全部 SVG 路径；不涉及 `THIRD_PARTY_NOTICES.md`

## 3. 运动规则

| 状态 | 水平移动 | 帧率 |
| --- | --- | --- |
| idle / packup | 走动（现状速度） | 现有 tick |
| rain / cold | 原地（0 速） | 现有 tick（腿仍交替） |
| sleep | 原地，腿部静止 | 仅 Zzz 动画 |
| celebrate | 原地上下弹跳（`translateY` 0 → −6 → 0，0.6s） | 现有 tick |

- `prefers-reduced-motion`：关闭位移、抖动与弹跳，只保留静态道具（伞 / 围巾 / Zzz 静态）
- 常亮屏友好：状态判定只在数据到达时算一次（时间 60s、天气 5min、倒计时 1s），不新增轮询

## 4. 文案

底部 caption 现在是 `像素猫` + 随机模式倒计时。改为：

```
像素猫 · 打伞        02:31     ← 状态非 idle 时在名字后追加；idle 时不显示
像素狗 · 还有 25 分钟下班        ← packup 用倒计时文案
像素猫 · 已下班                 ← celebrate
像素猫 · 睡了                   ← sleep
```

- 全部 `--muted`，与现有 caption 同字号
- 状态短语由状态表直接映射，不做随机台词（避免"宠物在胡说"）

## 5. 配置

`ScreenDisplayConfig` 新增 `petLive: Bool`（默认 `true`）：

- 开：按上面的状态机响应真实数据
- 关：只有 idle（等价于现在的行为），给"不想让宠物跟着天气变"的人一个出口

设置位置：副屏 →「副屏显示与桌宠」里加一个开关「宠物随环境变化（天气 / 时间 / 下班）」。

## 6. 接入点（实现时）

| 位置 | 改动 |
| --- | --- |
| `PET_NAMES` / `petSvg` | 道具层独立成 `petProps(state)`，与 `petSvg(kind, frame)` 组合 |
| `petTick` | 依据 `petState.behavior` 决定速度与位移 |
| `loadWeather` / `loadCountdown` / `loadMacTime` | 各自成功后调用 `petEvaluateBehavior()` |
| `applyDisplay` | 读 `petLive`，关闭时强制 idle |
| caption | `petRenderCaption` 追加状态短语 |

## 7. 验收

1. 把 Mac 时间调到 02:00 → 三只宠物都进入 sleep，显示「睡了」
2. 把天气城市换到雨天城市 → 撑伞 + 雨滴，caption「打伞」
3. 下班倒计时剩余 30 分钟内 → 看表；到点 → 弹跳 + 星星
4. 断网（天气失败）→ 回退 idle，不显示错误
5. 关掉「宠物随环境变化」→ 行为与今天一致
6. `prefers-reduced-motion` 开启 → 无位移、无抖动，道具仍在
7. 三档尺寸 s/m/l 下道具不越界、不遮住宠物眼睛

# 附：性能审计（长时间常亮副屏）

> 副屏的典型用法是「手机插电、Wake Lock 常亮、整天显示」。这类场景对 UI 卡顿的容忍度很低：
> 一次掉帧在秒针/宠物身上就能看出来，而且长时间高占用会发热、掉电、被系统降频。
> 下面先审计**现有**页面的开销，再规定新增状态化必须遵守的性能约束。

## A1. 现状审计（读代码得到的结论）

| 项 | 现状 | 问题 |
| --- | --- | --- |
| rAF 循环 | **两个独立循环**：`loop()` 时钟 + `petTick()` 宠物，都是 60fps 无限循环 | 120 次回调/秒；两个循环各自唤醒 CPU |
| 强制同步布局 | `petTick` **每帧**读 `petBox.clientWidth`、`petWalker.offsetWidth` | 60fps × 2 次布局读取 = 120 次/秒 reflow 风险（读→写 transform→再读，典型 layout thrash） |
| DOM 重建 | 换腿帧时 `petSprite.innerHTML = petSvg(...)`，每 280ms 一次 | 3.5 次/秒重新解析 20–30 节点 SVG，中低端机明显掉帧 |
| canvas 重绘 | `loop` 每 66ms 全量重绘：60 刻度 + 12 个 `fillText` 数字 + 3 指针 + 2 圆点 | 15 次/秒 × ~75 次绘制调用 ≈ 1,100 次/秒；`fillText` 在移动端最贵 |
| 定时器 | 宠物 caption 1s、倒计时 1s、`/api/time` 60s、天气 5min、long-poll 15s | 多个独立唤醒，单次便宜但叠加 |
| CSS 动画 | 倒计时图标 3 个 `cd-tick` | 数量少，暂不构成问题 |

结论：**卡顿主因不是动画数量，而是 (1) 双 rAF 循环 (2) 每帧强制布局 (3) 每 280ms 重建 SVG (4) 15fps canvas 文本重绘。**

## A2. 硬约束（新增状态化必须满足）

1. **单一 rAF 主循环**：合并时钟与宠物；宠物限 30fps，时钟限 1fps。
2. **零每帧 DOM 读**：`petMaxX` 等尺寸只在 `ResizeObserver` / `applyDisplay` / 切换尺寸时算一次，缓存到 `petState`。
3. **零 SVG 重建**：两帧腿、全部道具常驻 DOM，切换只改 `data-frame` / `data-state` 属性，由 CSS 控制显隐与动画。
4. **动画只用 `transform` / `opacity`**：任何状态同时最多 2 组道具动画，不使用 `will-change` 常驻。
5. **时钟降到 1fps（秒跳变）**：秒针改为整秒跳动，只在这一秒变化时重绘一次。
6. **可见性**：`document.hidden` 时停掉 rAF、停止所有动画（现有 `visibilitychange` 已有，需覆盖新动画）。
7. **低动效**：`prefers-reduced-motion` 下取消位移/抖动/弹跳，仅保留静态道具。

## A3. 优化前后对比（同一副屏，竖屏 390×844）

| 指标 | 现状 | 目标 |
| --- | --- | --- |
| rAF 回调 | 120 次/秒 | 60 次/秒（单循环） |
| 每帧强制布局 | 每秒 120 次 | **0**（缓存尺寸） |
| SVG 解析 | 3.5 次/秒 | **0**（属性切换） |
| canvas 绘制 | 15 次/秒 ≈ 1,100 draw call/秒 | 1 次/秒 ≈ 75 draw call/秒 |
| 常驻动画 | 3 个 | ≤ 4 个（同状态最多 2 个道具 + 指针） |
| 长时间表现 | 有掉帧、发热明显 | 秒针每秒一跳，宠物 30fps，无可感知卡顿 |

## A4. 可选（本轮不做）

- **时钟改 SVG/CSS 指针**：静态表盘只画一次，秒针用 CSS `rotate` 平滑（负 `animation-delay` 起步），完全不吃 JS 帧。收益再降 ~75 draw call/秒，但属于重构时钟渲染，单独评审。
- **省电模式**：5 分钟无触摸且状态未变 → 宠物降到 10fps。需要真机实测再定阈值。
- **`?perf=1` 本地 FPS 面板**（只读、不影响数据），用于真机回归取证。

## A5. 新增的验收项（性能）

1. Chrome Performance 录制 60s：主线程 `Layout` 事件 **< 20 次**（现状约 7,000 次）
2. 无 `Recalculate Style` 长任务超过 16ms
3. 页面隐藏再恢复：rAF 与动画都停止/恢复，无残留定时器
4. 连续显示 2 小时，`Activity Monitor` 里该标签页 CPU 平均值 < 5%（M 系列 Mac 上的 Chrome 模拟）
