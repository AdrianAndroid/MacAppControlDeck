# v0.4.1 · PureMac 柠檬式菜单栏与 UI v3

2026-11-24

本版本承接 v0.4.0（自动升级，未单独打 tag），把 PureMac 系统工具模块、菜单栏三状态项与实时网速一并正式发布。

## 新增

- **菜单栏三状态项**：CPU / MEM / 网速拆成三个独立状态项，可分别点击与单独勾选显示；从左到右 CPU → MEM → 网速。
- **实时网速**：网速项上下两行显示 ↑上行 / ↓下行速率（K/s·M/s 自动切档），用 `getifaddrs()` 差分采样活动网卡累计字节，零 TCC 权限。
  - 定宽显示：数值右对齐填 5 字符 + 等宽数字字体 + 固定列宽，速率位数变化时宽度不抖动、小数点对齐。
  - 上下两行同字号同色（仅靠箭头区分方向），对齐腾讯柠檬的视觉形态。
- **MEM 内存占用菜单**：点击 MEM 状态项弹出柠檬式菜单——顶部内存占用百分比，下方按内存降序列出运行中应用（图标 / 名称 / 占用大小），每个用户应用行带「关闭」按钮可直接正常退出，底部提示「关闭将直接退出程序，请先保存重要数据」。
  - 点击时即时采样（`proc_pidinfo`），不常驻额外后台任务；系统 / root 进程的「关闭」禁用。

## 变更

- **PureMac UI v3**：保留顶部页签导航，内容区按「入口 → 扫描 → 结果 → 确认」四层交互重组；统一入口卡、路径进度扫描态（不显示百分比）、分组折叠、大文件分类 tab、进程状态胶囊；取消扫描走二次确认；修复菜单入口消失与状态栏数字被裁。
- **清理范围一致性**：扫描根与清理允许范围统一由 `SystemToolScanRoots` 定义，修复大文件 / 开发缓存扫描结果清不掉的缺陷。
- 退出应用的安全策略提取为共享 `ProcessTerminationPolicy`，主窗口进程页与菜单栏内存菜单共用，避免两处规则漂移。

## 构建与升级

- `Info.plist`：`CFBundleShortVersionString` 0.4.0 → 0.4.1，`CFBundleVersion` 6 → 7。
- 推送 `v0.4.1` 标签后，GitHub Actions 自动构建 universal 包、固定签名、EdDSA 签名 appcast 并发布 Release。
- 发版流水线 `runs-on` 由 `macos-14` 直迁 `macos-26`：macOS 14 镜像已于 2026-11-02 退役；先试 `macos-15` 发现其 Xcode 16.4 / macOS 15 SDK 缺少 macOS 26 才有的 `SCScreenshotConfiguration` / `SCScreenshotOutput`（截图模块用到），编译报 `cannot find type in scope`。`macos-26` 的 Xcode 26 / macOS 26 SDK 与本机一致，可编译。
- `Build/package-release.sh` 的 `swift build` 补 `--disable-sandbox`（SwiftPM 在受限环境会因 sandbox-exec 权限失败），并把 bin 目录改用全局变量承接，不再用 `$(... | tail -1)` 吞掉编译输出——CI 失败时能看到真实错误而不是只有一行 exit code。
- **EdDSA 密钥轮换**：v0.4.1 是首个实际发布、内置 Sparkle 的版本（v0.4.0 未发布），本机作为新发版机没有与旧 `SUPublicEDKey` 配对的私钥，故生成新密钥对并更新 `Build/Info.plist` 的 `SUPublicEDKey`。v0.3.1 及更早版本不含 Sparkle、不校验签名，因此换公钥不影响任何已发布用户的升级链；已安装的开发版构建需手动装一次 v0.4.1 才能建立自动升级链。
- 三个发版 Secrets（`DECK_SIGN_P12_BASE64` / `DECK_SIGN_P12_PASSWORD` / `SPARKLE_ED_PRIVATE_KEY`）已配置到仓库；签名 p12 只含 `MacAppControlDeck Self-Signed` 单身份，其 designated requirement 与公司电脑发布的 v0.3.1 同为 `certificate root = H"e8357462…"`，升级后 TCC 授权不失配。
- 装 v0.4.0 之后可直接从 App 内「检查更新…」升级；首次安装仍需手动装一次（包未公证，右键「打开」）。升级后辅助功能 / 输入监控 / 屏幕录制 / 自动化授权保持有效。

## 补记：本机成为正式发版机（2026-11-25）

v0.4.1 发布时本机是「接入更新后第一次发布」，发版链路实际依赖临时私钥文件与手工命令：临时文件清理后，本机只剩登录钥匙串里的 EdDSA 私钥，非交互读取会弹「允许访问钥匙串」授权框并永久挂起，导致本机无法独立重签 appcast；CI 又因 `macos-26` arm64 runner 排队只能作为备份。用户明确后续重点发布都在这台自己的电脑上完成，因此补做：

- 用 Sparkle `generate_keys -x` 把私钥导出固化到 `~/.config/macappcontroldeck/sparkle_ed_key`（600 权限、不进仓库），与钥匙串项、仓库 Secret `SPARKLE_ED_PRIVATE_KEY` 为同一份；验证重签 v0.4.1 appcast 的 `edSignature` 与线上完全一致，**未轮换 `SUPublicEDKey`**，存量升级链不受影响。
- 新增 `Build/publish-local.sh` 一键发布（凭据自检 → 构建 → 签名 → 校验 → 创建 Release → 线上复核），`make-appcast.sh` 改为文件私钥优先、禁止回退会弹窗的钥匙串。
- `.github/workflows/release.yml` 增加幂等 gate：本机已发布时 CI 整体跳过；`workflow_dispatch` 支持指定 tag 补发。
- 同步当前证书指纹 `E8357462…`（此前活跃文档中的 `145AEA72…` 已过时；历史归档文档保留原记录）。

SOP 见 [本机发布手册](local-publish.md)，规格见 [local-release-publishing](../../openspec/specs/local-release-publishing/spec.md) 与 [OpenSpec 变更](../../openspec/changes/archive/2026-11-25-make-local-machine-primary-release-publisher/proposal.md)。

## 已知限制

- `getifaddrs` 的 32 位累计字节长时间会回绕，差分时归零处理，最坏某次速率显示 0、下一采样恢复。
- 第三方签名的 1KiB 批量化取整使低速显示略粗，量级正确。
- 菜单栏内存菜单的「关闭」为普通退出（非强制），已提示先保存数据；不提供强制退出，避免误杀未保存内容。
- 更新包不做增量（每次下完整 universal ZIP）；不接入 Apple 公证，首次安装仍需右键打开。
