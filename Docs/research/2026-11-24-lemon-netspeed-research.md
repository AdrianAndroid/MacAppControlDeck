# 腾讯柠檬「网络速度监测」功能调研

- 日期：2026-11-24
- 被测对象：Tencent Lemon（腾讯柠檬清理）5.3.7（本机 `/Applications/Tencent Lemon.app`，官网最新 5.3.9）
- 目的：为 PureMac 实现网速监测提供「柠檬怎么做 + 技术上怎么做」的可落地依据
- 证据来源：本机真实菜单栏截图 + App 内二进制/本地化字符串逆向 + 官方文档与第三方技术文章
- 安全：全程只读观察与坐标截图，未点击任何清理/卸载/删除操作，未改动系统网络设置

## 1. 结论先行

柠檬的「网速监测」不是一个功能，而是**三件不同的事**，不要混为一谈：

| # | 功能 | 形态 | 触发 | PureMac 是否借鉴 |
| --- | --- | --- | --- | --- |
| A | **实时网速状态项** | 菜单栏常驻两行数字（↑上传 / ↓下载） | 常驻采样，无需打开窗口 | ✅ 核心借鉴对象 |
| B | 网络测速 | 独立窗口「网络测速，监控流量」，点「开始测速」主动跑 | 手动 | ⚠️ 可选，非"监测" |
| C | 流量监控 / 网络端口 | 按进程实时速率表、`netstat`-based 端口列表 | 手动打开子页 | ⚠️ 后续可选 |

用户说的"网络速度监测"通常指 **A（菜单栏实时网速）**——这也是柠檬官网主打的"状态栏实时显示"。本调研以 A 为实现目标，B/C 作为可选扩展记录。

## 2. 柠檬的实际形态（实测证据）

### 2.1 菜单栏状态项

实测截图（本机 5.3.7，菜单栏右侧放大）：

```
...  30%  |  58%  |  52°C  | ↑34.8 K/s   ...
     CPU     MEM     SEN    ↓10.8 K/s
```

- **紧凑合栏**：CPU / MEM / 温度 / 网速四项在**同一状态项组内**，用竖线 `|` 分隔；这与 PureMac 当前「CPU、MEM 各自独立状态项」不同。
- **网速两行**：上行 `↑`（上传）在第一行、下行 `↓`（下载）在第二行；每行 = 箭头 + 数值 + 单位。
- **单位动态**：实测出现 `K/s`、`KB/s`（旧版文案），二进制中还有 `%ld KB/s`、`%.2f MB/s`、`%ld Kbps`、`%ld Mbps`——按量级自动切换单位。首帧无数据时显示 `0KB/s` / `0.0KB/s`。
- **精度**：K/s 保留 1 位小数（如 `34.8 K/s`），与截图一致。
- 采样由常驻进程 `LemonMonitor`（登录项）承载，主 App 未启动也会显示——PureMac 同样有常驻状态项与 `SystemSampler`，架构一致。

### 2.2 网络测速窗口（B，非本次目标）

从 `LemonNetSpeed.framework` 的 `zh-Hans.lproj/Localizable.strings` 还原出完整界面结构：

- 标题「网络测速，监控流量」/ 副标题「便捷网络测速，实时了解当前网络状况」
- 三个指标：下载速度、上传速度、网络延迟；主按钮「开始测速」/「取消」/「重新测速」
- 测速过程文案「等待测速」→「延迟测量中」；结果有网络评级（还需努力 / 及格 / 良好 / 优秀 / 卓越 / 专线）
- 无网络时「网络未连接 / 请检查网络情况，正常连接后再进行网速检测」
- 这是**主动向测速服务器收发数据**得到带宽结果，与"实时监测当前流量"完全不同。

### 2.3 流量监控与端口（C，非本次目标）

- 「流量监控」页：应用名称 / 当前下载速度 / 当前上传速度 / 下载速度 / 上传速度——按进程列出实时速率（类 `nettop`）。
- 「网络端口」页：`netstat -vatn | grep -E 'tcp4|tcp6|...'`，列「端口 / 协议 / 系统服务说明 / 状态 / 允许入站」，状态含连接/监听/本地连接/远程连接，可「结束进程」。

## 3. 技术实现（柠檬怎么做 + 我们怎么做）

### 3.1 柠檬的实现线索（逆向二进制）

`LemonNetSpeed.framework` 与 `LemonMonitor` 二进制中可见：

- 数据模型字段：`bytesRecv` / `bytesSend`（累计收发字节）、`bytesRecv_rt` / `bytesSend_rt`（实时值）
- 定时：`scheduledTimerWithTimeInterval:target:selector:...repeats:` —— 定时轮询
- 格式化类 `QMNetworkSpeedFormatter`，方法 `convertSpeedToString:`
- 速率算法：对累计字节做**定时差分**（`当前累计 - 上次累计` ÷ 间隔）
- 状态项显示用 `K/s`、`KB/s`、`MB/s`、`Kbps`、`Mbps` 多档单位

即柠檬核心算法 = **读系统累计流量 → 定时差分 → 单位格式化**，没有神秘依赖。

### 3.2 macOS 读取累计流量的三种 API（本项目选型依据）

| API | 优点 | 坑 | 适用 |
| --- | --- | --- | --- |
| `getifaddrs()` → `if_data.ifi_ibytes/obytes` | 公开 API、简单、无需权限；**本机实测可用** | 32 位字段会溢出（现代系统跑久了回绕）；第三方签名有 1KiB 批量化 | 短时速率显示（状态项），够用 |
| `sysctl(CTL_NET, ..., NET_RT_IFLIST2)` | 64 位计数，不过早溢出 | 第三方签名下数值按 1KiB 取整、Ventura 13.2.1 有 4GiB 截断 bug | 需要较准总量时 |
| `nettop` / 私有 NetworkStatistics.framework | 活动监视器同源、按进程 | 私有 API 或被 `sandbox` 挡；按进程 overhead 高 | 流量监控（C） |

**本项目选 `getifaddrs()`**：只做状态栏实时速率（差值），32 位回绕在差分时做「负值归零」处理即可，1KiB 批量化对"看个大概速率"无影响，且无需任何 TCC 权限、实现最轻。

### 3.3 本机可行性验证（已实测）

用独立 Swift 脚本调 `getifaddrs`，每 2 秒差分：

```
活动接口: en0/en1/en6/en10/en14 + utun0...utun6
en1: ↓4.5 KB/s  ↑12.6 KB/s   （2 秒差分）
en0: ↓0.7 KB/s  ↑0.5 KB/s
```

结论：读数与柠檬状态栏同量级（几 KB/s），方案可行。注意需**聚合所有活动物理接口**（en*/utun*，跳过 loopback 和全零接口），否则会漏流量。

## 4. 给 PureMac 的实现方案（待用户确认后开工）

### 4.1 目标（最小可用，对齐柠檬 A）

菜单栏新增一个网速状态项，两行显示 ↑上传 / ↓下载，动态单位，不占 TCC 权限；`SystemToolSettingsView` 增加勾选开关（与 showCPU/showMEM 同款）。

### 4.2 落地改动点（复用现有架构，改动面最小）

| 文件 | 改动 |
| --- | --- |
| `SystemSampler.swift` | 新增 `@Published uploadBytesPerSec/downloadBytesPerSec`；在现有 2s 定时器里加 `sampleNetwork()`：`getifaddrs` 读累计字节 → 与上次差分 → 速率；处理回绕与接口聚合 |
| `SystemToolModule.swift` | 新增 `netStatusItem`；`setupStatusItems` 按 `showNetSpeed` 创建/销毁；复用 `StatusMetricView` 自绘两行（↑/↓ + 值 + 单位），跟随深浅色；采样订阅更新 |
| `SystemToolSettingsView.swift` | 加 `showNetSpeed` 开关 + 示例卡片，与 CPU/MEM 三项并列 |
| `openspec/` | 先建变更记录（项目规范要求「先建变更再实现」），delta 写 `system-cleaner` 的网速要求 |

### 4.3 关键设计决策（沿用已确立的约定）

- **单位格式化**：B/s → K/s → M/s 自动切换（柠檬用 K/s、KB/s、MB/s 混用；我们统一 `K/s`）；保留 1 位小数。
- **定宽显示（关键，对齐柠檬）**：柠檬网速列宽度恒定，不随数值位数变化。实现用 figure space (U+2007，与数字等宽) 将数值右对齐填充到 5 字符（`   0.0`~`999.9`），单位固定 3 字符，配等宽数字字体 9pt；网速列设固定宽度。**上下两行统一 9pt、统一 `.labelColor`，只靠 ↑↓ 区分方向**——早期实现用 ↑绿/↓蓝 + 11pt/8pt 双字号，既抖动又不统一，已按柠檬形态纠正。
- **零值与回绕**：无数据 `0 KB/s`；累计值下降（接口重置/回绕）当次速率记 0，不用负数。
- **接口选择**：聚合 `en*` + `utun*`，跳过 loopback（`lo0`）与 `ifi_ibytes==ifi_obytes==0` 的空闲接口；VPN 走 utun 也能计入。
- **权限**：零 TCC 权限，`getifaddrs` 是公开 API。
- **不动清理引擎与安全边界**（延续 v3 原则）。
- **不实现 B（主动测速）/ C（按进程流量）**，除非用户另行要求——它们与"监测当前网速"不同，且 C 需要 nettop/私有 API、overhead 高。

### 4.4 验收

- 菜单栏显示两行 ↑/↓ 速率，量级与活动监视器/柠檬一致；拔插网线或开关 VPN 后速率归零/恢复；回绕不出现负数。
- `swift build` + `SystemToolTests` 全绿；覆盖安装截图确认数字完整（复用 StatusMetricView，不重演被裁问题）。

## 5. 用户确认的实现决定（2026-11-24）

1. **范围**：仅实现菜单栏实时网速（A）；不做主动测速窗口（B）与按进程流量/端口（C）。
2. **显示形态**：合并成一组（柠檬原样）——把 CPU / MEM / 网速放进同一状态项，用竖线分隔。
3. **单位**：`K/s`、`M/s`（柠檬原样，不写 B）。

据此进入实现：先建 OpenSpec 变更，再改 `SystemSampler` / `SystemToolModule` / `SystemToolSettingsView`。
