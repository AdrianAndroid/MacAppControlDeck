# 副屏桌宠方案调研（2026-11-26）

> 目标：副屏底部宠物卡片目前只有 cat / dog / robot 三只 inline SVG 左右横移，观感单调。
> 本文只做调研与方案比较，不含实现。

## 1. 现状与可用素材

| 项 | 现状 |
| --- | --- |
| 渲染 | `petSvg(kind, frame)` 返回 inline SVG，viewBox `64×48`，只有两帧腿部交替 |
| 行为 | 水平往返移动；`prefers-reduced-motion` 时停在中间 |
| 交互 | 无（副屏只读，无点击反馈） |
| 配置 | `petMode` 固定/随机、`petId`、`petInterval`、`petVisible`、尺寸 `s/m/l` |

副屏前端**已经拿得到**的真实数据，可直接驱动宠物行为：

- Mac 墙钟（`/api/time`，含跨时区校正）
- 天气：`now`（温度/体感/图标）、`daily`（5 天）、`hourly`（现在 + 4 小时）、`today.precipProbability`
- 下班倒计时：`phase`（working / off / …）、`progress`、目标时间
- 月历：节假日 `休/班` 标记
- 宠物配置：模式、当前宠物、随机间隔

## 2. 参考项目（含许可结论）

| 项目 | 做法 | 许可 | 可借鉴 | 能否直接用 |
| --- | --- | --- | --- | --- |
| `Cybing521/petmux` | Canvas **程序化像素画 + 自动描边**，4 只原创元素宠物，6 状态（idle / working / waiting / done / error / sleep） | MIT | 程序化绘制（零素材授权风险）、状态机 | 思路可用，代码需按我们形态重写 |
| `xiaominaimoyu/desktop-pet-demo` | 15 个状态绑定 AI 编程工具事件，气泡提示 | MIT | "宠物反映真实状态"、气泡文案层 | 思路可用 |
| `adryd325/oneko.js` | 经典鼠标追随猫（sprite 帧 + 行为切换） | **未标注许可** | 待机/追随的行为切换 | 不引入素材与代码；**跟随行为已在副屏试做过一版并撤回**（长期常亮屏上手指跟随容易误触/分心，见下） |
| `CommentOut64/web-mascot` | Shimeji 行为 XML 移植到 Web，拖拽/掉落阻力物理 | 引擎 **GPL-3.0**，素材 CC-BY-NC-SA | 多行为链、物理手感 | **不可引入**（GPL 传染 + 素材禁商用） |
| `Innate-Labs/desktop-pet` | Electron 多角色像素桌宠（8 角色可切换） | MIT | 多角色切换的产品形态 | 同左 |

**结论**：值得吸收的只有三条 —— ①程序化绘制（不背素材许可债）②状态机 + 真实数据驱动 ③轻量物理手感。第三方素材/引擎一律不搬，全部自绘 SVG/Canvas。

## 3. 候选增量方案

### 方案 1：新增「水豚 Capybara」——松弛感符号（推荐首发）

```
  ┌──────────────────────────────┐
  │        ( • ᴗ • )             │  待机：头顶橘子，尾巴缓慢摆动
  │      ╱▔▔▔▔▔▔╲   ~~~~        │
  └──────────────────────────────┘
         下雨 / 降水 > 60%
  ┌──────────────────────────────┐
  │      ╱▔▔▔▔╲  ☂  ╱▔▔▔╲       │  温泉池 + 打伞（水豚名场面）
  └──────────────────────────────┘
```

- 形态：圆角矩形拼装 + 一个橘子，2–3 帧（呼吸、尾巴摆）
- 为什么选：2024–2026 全网"松弛感"符号，辨识度高、只靠圆角矩形就能画得很像
- 成本：~150 行（SVG + 状态切换）
- 风险：低（无外部素材）

### 方案 2：新增「史莱姆 Slime」——弹跳物理

```
   ╭───╮        ╭─────╮        ╭──╮
   │ ● │   →    │  ●  │   →    │● │   落地压扁、起跳拉长
   ╰───╯        ╰─────╯        ╰──╯
```

- 形态：Canvas 或 SVG `scaleY/scaleX` 弹簧，落地 squash & stretch
- 为什么选：和现有"两帧腿"完全不同的观感，动起来最有生命感
- 成本：~100 行（弹簧 + 落地判定）
- 风险：低；但要控制帧率（副屏是常亮屏）

### 方案 3：不给新宠物，给所有宠物「状态」——数据驱动行为

```
时间        天气              下班倒计时        行为
00:00-06:00   —               —               😴 睡觉（Zzz 飘）
—            降水 ≥ 60%       —               ☂ 打伞
—            晴 & 温度 < 5    —               🧣 围巾 / 发抖
—            —               剩余 ≤ 30 min    ⌚ 看表、收拾包
—            —               到点             🎉 欢呼跳
周末 / 休      —               —               🛋 躺平
```

- 成本：~120 行（复用现有 SVG，加状态节点 + 气泡文案）
- 收益：三只旧宠物立刻不单调，且行为**和副屏内容同源**（不是随机动画）
- 风险：状态判定的边界（天气暂不可用时回落到待机）

### 方案 4：触摸反馈（只读边界内）——已评估后放弃

- 曾实现"跟随手指 / 鼠标"（oneko 式），实测后**撤回**：副屏长期挂在手机上，手指一碰猫就跑，容易误触、也容易把宠物带离视线中心；作为一块"看着的屏"，静态状态化比交互更稳。相关代码与 `petChase` 配置已全部移除。

### 方案 5：多宠物同屏 1–3 只

- `petCount` 配置，多只在卡片里各走各的，彼此避让
- 成本：中高（布局、避让、性能）；收益不如 1–3
- 建议：暂不做

## 4. 建议

先做 **方案 1（水豚）+ 方案 3（状态驱动）**，一次交付：

1. 新增 `capybara` 到 `PET_KEYS / PET_NAMES`，与 cat / dog / robot 并列，Mac 端设置里可选
2. 给三只旧宠物 + 水豚加统一状态机（睡觉 / 打伞 / 发抖 / 看表 / 欢呼 / 待机）
3. ~~点击 / 跟随等本地反馈~~：试做后撤回，副屏保持无交互

不做：方案 5（多宠物）、方案 2（史莱姆）留作下一轮。
